1 Fix Quarto + GitHub Pages Double-Build Issue

1.1 The Problem

When you push to main, GitHub Actions rebuilds the site even though you’ve already built it locally with quarto publish gh-pages. This happens because: 1. Your .gitignore excludes _book/ 2. GitHub Action still runs the Quarto build step 3. Two builds = slower deployment + potential inconsistencies

1.2 The Solution: Build Once, Deploy to GitHub

1.2.1 Step 1: Update .gitignore

Comment out or remove the _book/ entry so you can commit the built files:

# Before:
/_book/

# After:
# /_book/  # now committing built files

1.2.2 Step 2: Update GitHub Actions Workflow

Replace your publish.yml with a deploy-only workflow that skips the build:

name: Deploy to GitHub Pages

on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: write

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - name: Check out
        uses: actions/checkout@v4

      - name: Deploy _book to gh-pages
        uses: peaceiris/actions-gh-pages@v3
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          publish_dir: ./_book

This uses peaceiris/actions-gh-pages which simply copies the pre-built _book/ directory to the gh-pages branch—no rebuild needed.

1.2.3 Step 3: Local Workflow

# 1. Make changes to your .qmd files
# 2. Build locally
quarto render

# 3. Commit everything (including _book/)
git add -A
git commit -m "Update course notes"

# 4. Push to main
git push origin main

# 5. GitHub Actions deploys instantly (no rebuild)

1.2.4 Step 4: Optional - Add _book to Git (if needed)

If Git hasn’t picked up _book/ yet, explicitly add it:

git add _book/
git commit -m "Add built site"

1.3 Benefits

✅ Single build step (local)
✅ Instant deployment to GitHub Pages
✅ No runner waste rebuilding
✅ Built site always in sync with source

1.4 Files Changed

  • .gitignore — uncomment _book/
  • .github/workflows/publish.yml — switch to deploy-only workflow
